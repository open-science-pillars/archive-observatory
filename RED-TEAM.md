# Red-Team Register: Archive Observatory

Adversarial review run against the design before any implementation
shipped, per the build request. Each finding names the attack, the
consequence if unmitigated, and the mitigation now designed into the kit.
The red-team agent (agents/red-team.md) carries this register as its
rubric for every subsequent PR; a finding here is closed only by a
designed-in control, never by intent.

| ID | Attack | Consequence unmitigated | Designed-in mitigation | Residual |
|---|---|---|---|---|
| R1 | Publishing cross-provider inconsistency diffs reads as public shaming of 12 DAACs | The SET partnership dies before it starts; the Ian capstone is poisoned by association | docs/publication-policy.md: aggregate statistics public by default; per-provider detail delivered privately with a 30-day window; per-collection public reports and badges strictly opt-in; PO.DAAC opts in first as the exemplar via the co-build | A provider can still dislike aggregate truth; the policy makes the disagreement about numbers, not manners |
| R2 | OSP misstates a requirement (paraphrase drift from ESDIS/UMM docs) and flags providers wrongly | False authority; findings dismissed wholesale after one wrong rule | Rule schema separates MUST (documented requirement, source section cited) from SHOULD (ARC framework best practice, attributed to ARC, never presented as mandate); every finding cites rule id and source; provenance flags (esdis-doc-pending) block a rule from MUST class until the citation is verified; disputed rules carry the disputed key and an upstream question | Interpretation disputes remain; they route upstream by design |
| R3 | pyQuARC coupling rots: rules change across versions, deps are dated (urllib3/six breakage on Python 3.13 observed during this build; package installs from GitHub, not PyPI; python_requires >=3.8) | Irreproducible findings; silent verdict drift on upgrade; broken installs | Harness pins the git tag (v1.3.0) and a compatible Python in its PEP 723 block; every receipt records pyquarc_version and a sha256 of the effective ruleset files; upgrades land only through a verdict-diff gate (old vs new on the same records) reviewed like a spec-watch delta | pyQuARC's own false-negative coverage (roughly 58 percent of manual findings auto-flagged per the ARC poster) means reports must and do state coverage honestly |
| R4 | Sweeps hammer CMR (49k+ collections) and read as abuse | Rate limiting, Ops complaints, reputational harm at the exact agency we serve | Client-Id header on every request; throttled, incremental sweeps keyed on revision dates; monthly schedule, never continuous; scope starts at POCLOUD plus volunteers and grows by invitation | Scale-up needs an Ops conversation; the SET is the natural broker |
| R5 | Metadata is third-party text; adversarial strings in CMR records reach agent contexts (prompt injection via abstracts, URLs) | An agent consuming reports or MCP results executes planted instructions | The gate path is deterministic, no LLM anywhere in sweep, harness, or attester; reports render metadata values as quoted data; SPEC section 5.8 posture extended: observatory artifacts are declarative, and agents never treat metadata content as instructions | Agent-side consumption outside OSP surfaces is uncontrolled; the concept documents the rule for everyone else |
| R6 | Badge gaming: a provider hand-edits a badge claim or replays a stale receipt | The badge becomes decoration and the attestation brand dies | Badges are emitted only by the observatory's own scheduled runs; receipts publish alongside with code hash, ruleset hash, record concept-ids and revision-ids; the attester rejects receipts whose revision ids no longer match CMR | Same trust root as the budget-closure badge; acceptable |
| R7 | A personal-hat project running a compliance observatory over NASA archives reads as freelance oversight | Institutional allergy; doors close | Framing and word choice throughout: a community mirror, not enforcement; reports are offers of help; rule disagreements route upstream to NASA-IMPACT issues rather than being adjudicated by OSP; explicit non-affiliation note on every published artifact; the SET co-build makes it with the archive, not at it | The frame must be maintained in every artifact; the red-team agent checks tone as part of R7 |
| R8 | Dated findings flood the knowledge repo | The bundle drowns in expired state and the signing model degrades | Reports and receipts live in the observatory repo only; a finding graduates into nasa-daac-knowledge solely when it is a durable fact a steward will sign (a standing rule, a persistent cross-archive pattern), per the horizon discipline already governing the bundles | None significant |
| R9 | Multi-agent red-teaming devolves into theater (vague concerns, infinite rounds) | Process cost without safety gain | agents/red-team.md fixes the contract: findings must cite a register ID or propose a new one with attack and consequence; verdict is block or approve, recorded as a file in the PR; two rounds maximum, then the human steward decides | Human judgment remains the backstop, as it should |
| R10 | Credential creep: someone adds an authenticated call and the no-login invariant silently dies | The observatory's cleanest property (runs credential-free, forkable by anyone) is lost | CI greps the tree for netrc, token, Authorization, and EDL patterns and fails on match; workflows declare no secrets; the invariant is stated in the README as a property, not a preference | None; the check is dumb and that is its virtue |
| R11 | Verification-chain masking: a local gate run piped through tail, head, or grep swallows a failing exit status, so a broken gate commits and pushes as green (observed 2026-08-30, commit 00e9290: the make_badge selftest crashed on a missing dependency and the pipe to tail masked the crash) | Gates become decoration; the receipts-on-everything property dies the first time a green turns out hollow | Every gate tool's selftest runs unmasked in ci.yml's gates step where a nonzero exit fails the job; a new gate tool lands its selftest in that step in the same PR that adds the tool; local verification reads exit codes, never output tails alone | Local habits stay maskable; CI is the backstop, and prompt disclosure of a masked failure is the norm the founding incident set |
| R12 | Silent input dropping: a crafted or malformed record is skipped before the rules run and the skip is disclosed only on stderr (observed 2026-08-31 in the producer-workflows PR: a draft record missing its ShortName was skipped, and a run that reported 2 swept, 50 percent and exit 1 became 1 swept, 100.0 percent and exit 0) | The report states a swept count and a pass percentage over a set that silently shrank, and --fail-on-must exits 0 over unchecked content, which is a gate reporting green on what it never examined | Skips are counted and named in the artifact itself, aggregate and detail, not only on stderr; a run that skipped anything cannot exit 0 under --fail-on-must | A producer can still hand over a file with nothing in it, which is visible in the count |

One meta-finding the exercise produced: the register itself is the most
reusable artifact. R1, R2, R5, and R7 apply to any OSP surface that
publishes findings about third parties, so the register graduates to
marketplace/docs as candidate doctrine once the SET co-build has
exercised it.
